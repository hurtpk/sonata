# Sonata Bot

An independent Discord moderation bot with the same commands available as slash commands and prefix commands. The default prefix is `,`. It uses a separate Discord application from Sonata Control Room. Bot credentials never belong in the client plugin or GitHub.

## Commands

There are 282 command forms under 100 top-level slash commands. Help has eight broad categories and emoji-only back, home and forward buttons. Both arrows browse All commands directly from the overview, without selecting a category. Prefix commands post only their final result or error, without a temporary checking message. `ping` measures a read-only Discord API request for prefix commands or the acknowledgement request for slash commands (including API queue wait), alongside the latest Gateway heartbeat round trip. A new connection shows an unavailable heartbeat value until an acknowledgement arrives.

## Profile

The bot uses Do Not Disturb and a custom `harmonizing N servers` status. The count follows active Gateway server membership, including joins and departures; temporary server outages do not lower it. Updates are coalesced to respect Discord's presence limits. The connection identifies as Discord iOS to request mobile presence; Discord controls how the client displays its badge.

`npm run setup -- --profile` applies the description in `profile/profile.json` and the fully transparent PNG banner, while keeping the existing avatar. The profile files contain no credentials. Run this only when intentionally changing the bot's public profile.

New server tools include configurable anti-raid and owner-only anti-nuke protection, server event logs, warning escalation and expiry, ban appeal forms, private tickets with file transcripts, persistent giveaways, and voice/music control panels. They reuse existing permissions, cases and scheduled releases. New automation stays off until configured. Read [server tools setup](SERVER_TOOLS.md) for commands, permission requirements and limits. Audit-based logs and anti-nuke require View Audit Log, now included in the invite.

`prefix` shows the current prefixes. `prefix set !` changes the server prefix with Manage Server; `prefix remove` resets it to a comma. `prefix self ?` sets your personal prefix across Sonata servers, and `prefix selfclear` removes it. A personal prefix does not disable the server prefix.

Administrators can configure up to five honeypot channels using `honeypot add #channel timeout`, `kick` or `ban`. Every human message in a trap can trigger the configured action, not only commands. Owners, bots, webhooks, moderators with relevant server permissions and configured exempt roles are excluded. Timeout traps last fifteen minutes. Actions check the bot's role hierarchy and permissions, create cases and use the moderation log. `honeypot remove` disables a trap; `honeypot exempt @role on` adds an exemption. Warn members about trap channels before enabling them.

`download message MESSAGE_ID` or a same-server message link copies a readable message's attachment as a real file. `download url`, `attachment`, `emoji` and `sticker` support direct Discord CDN files up to 8 MiB. Source message access and destination Attach Files permissions are checked. Reply to a message and send `,download` to copy its first sticker, otherwise its first emoji, otherwise its first attachment. Reply with `,emoji steal` or `,sticker steal` to import the matching expression; use `,emoji steal reply new_name` to rename an imported emoji. Source access is checked through a fresh message lookup; deleted, forwarded and cross-channel references are rejected. Unicode emoji use pinned [Twemoji artwork](https://github.com/jdecked/twemoji), with CC BY 4.0 credit on downloads and imports. Other downloads remain restricted to Discord files. `emoji steal/add/rename/remove/info/list` and `sticker steal/add/rename/remove/info/list` manage expressions with Discord's creation or management permissions. Emoji uploads are limited to 256 KiB, sticker uploads to 512 KiB. Animated emoji require an animated custom emoji mention. Discord still enforces slots and formats; Lottie stickers can be downloaded but cannot be imported through these commands. The updated invite requests Create Expressions, Manage Expressions and Speak.

`voicemaster setup #lobby #category` enables temporary join-to-create voice rooms with Manage Server and Manage Channels. Owners can use `name`, `limit`, `bitrate`, `lock`, `unlock`, `hide`, `unhide`, `permit`, `reject`, `transfer` and `reset` in their room. `claim` works when the old owner has left. One room per owner and up to 25 rooms per server are supported. Empty managed rooms are deleted; disabling creation keeps existing rooms until empty. Privacy controls preserve unrelated permission bits, and Discord administrators or explicit role/member allows can still grant access.

Music uses the optional [voice companion](music/README.md) on a separate Node host. `play`, `pause`, `resume`, `skip`, `stop`, `queue`, `nowplaying`, `volume`, `shuffle`, `remove`, `loop` and `seek` work through both prefixes and slashes. A caller must be in the bot's current voice channel; the bot needs Connect and Speak. Music reports offline until the companion connects, and reports playback only after confirmation. Song searches use SoundCloud. YouTube links depend on provider access and currently require sign-in from this Oracle host, so use SoundCloud links or track names here. The default companion permits one active server and stores its queue only in memory.

New server tools include `tag create/edit/delete/show/info/list`, `autoresponder add/update/remove/view/list`, `welcome` and `goodbye` with `add/remove/view/list/variables/test`, `autorole add/remove/list/enable/disable`, `joinlogs set/off/view`, and `autonick set/off/view`. All automation is inactive until configured. Tag edits and automation settings require Manage Server; autoroles also require Manage Roles, and automatic nicknames require Manage Nicknames. Reading tags is public within the server.

Welcome and goodbye templates support `{user}`, `{username}`, `{server}` and `{id}`. At most three channels per message type and five safe autoroles can be configured. Autorole audiences are `humans`, `bots` or `all`. Member automation skips jailed members and waits for membership screening before assigning roles or nicknames. Pending screening user IDs are retained for at most seven days and cleared on completion or leave. Roles are checked again at assignment, so a role that gained moderation permissions is skipped. Automation errors are saved as a generic diagnostic in server settings. Replies require an exact case-insensitive match, ignore bots, webhooks and commands, and post at most once per ten seconds per server. At most 20 reply triggers and 100 tags are supported. Trigger text and configured templates are stored; general chat messages are not archived. Automatic member event messages cannot ping users, roles or everyone. Busy queues can skip automatic events.

`poll create "Question here" Red|Blue` creates a 24-hour Discord poll with two to ten answers; `poll results MESSAGE_ID` displays available counts. These commands need Send Polls in addition to normal channel access. The invite requests that permission. Utilities include `choose`, `roll`, `coinflip`, `8ball`, `timestamp`, `snowflake`, `firstmessage`, `servericon`, `serverbanner` and `boosts`. `automod allowadd/allowremove/exemptrole/exemptchannel/words/config` manage only Sonata-owned rules. Word inspection shows the first ten entries of each list and their total counts.

Examples: `,tempban @member 7d repeated spam`, `/timeout member:@member duration:30m reason:spam`, `,case history @member`, `,case note 12 Appeal reviewed`, `,settings prefix !`.

The [complete command reference](COMMANDS.md) lists all syntax and permissions. `help` is paginated (`help 2`) and accepts command names (`help role add`). The bot has its own implementation inspired by the moderation, server and information categories in [Bleed's command catalogue](https://bleed.bot/commands).

`help` and `/help` open an interactive category overview. Choose a category or All commands from the dropdown, then use Previous, Home and Next to browse in the same message. Only the person who opened a menu can change it. Controls expire after 30 minutes; open a new help menu to continue. The controls also work on the private slash-command reply. They only browse command descriptions and never run moderation actions. Existing text page numbers and command-specific help remain available.

More examples: `,softban @member 1 spam`, `,nickname @member New name`, `,role add @member @role`, `,role color @role #a78bfa`, `,voice move @member #voice`, `,purge 25 bots`, `,pin MESSAGE_ID`, `,warnremove 12 appeal accepted`. Cleanup can select all, bots, humans, links, files, embeds or pinned messages. Pinned messages are kept unless the pinned filter is selected. At most 100 recent messages are inspected, so fewer matches may be deleted than requested. Case and ban browsing supports cursors, and role browsing supports pages. Information commands fetch current Discord data and do not build member or message archives.

Role assignment requires the selected role to be below both the moderator and bot, and its permissions must be held by both. Managed roles, the everyone role and the jail role cannot be edited through these commands. Jailed members cannot receive role changes or voice moves until released. Voice commands check permissions in the member's source channel and, for moves, the destination too. Warning removal marks warnings cleared and records who cleared them; existing cases, notes and evidence remain. Softban deletes up to the chosen number of days of messages, removes the member, then unbans them; an incomplete release is marked for staff review.

The invite requests Administrator. Sonata management commands require that permission on the bot; the caller still needs native or delegated command access and both role hierarchy checks still apply. Existing installations can update the bot role or use the invite again. Leave slash command permissions for the voice group open to staff who need it; each voice subcommand checks its own real Discord permission at runtime.

Prefix aliases include `b`, `tban`, `mute`, `unmute`, `warns` and `clear`. Quoted arguments are supported. Duration values include `30m`, `2h`, `7d` and `1h30m`. Timeouts and timed jails support up to 28 days; temporary bans support up to 365 days. Timed actions are checked each minute, so releases may happen after the exact expiry time. Service outages or Discord permission errors can delay them. Failed releases are recorded for staff review.

## Nickname policies, bot permissions and command insights

`nicknamepolicy setup 8 Member` enables server nickname filtering. `nicknamepolicy block admin` adds a literal blocked phrase, `unblock admin` removes it, and `exempt @role on` exempts a role. `check @member` previews without changing the name; `off` stops enforcement and `view` lists the rules. Names are normalized with NFKC and format characters removed before phrase and symbol checks. This is a configurable phrase filter, not automatic detection of every confusable character or staff identity. On joins and member updates, non-exempt names are replaced with the configured nickname. Bots, owners, administrators, pending or jailed members are excluded. Sonata needs Manage Nicknames and a higher role. Existing members are checked on their next member update. Corrections are recorded in cases and the configured moderation log. No account usernames are changed.

Real server administrators can use `fakepermissions grant @Staff ban` (alias `fakeperms`), `revoke @Staff ban` and `view [@role]`. Permissions are `ban`, `kick`, `timeout`, `warnings`, `messages`, `nicknames` and `cases`. These only authorize the corresponding Sonata commands. They do not change Discord role bits, bypass disabled commands, grant dashboard management, or bypass the caller's channel visibility, either role hierarchy, or the bot's native permissions. Grants and revocations are recorded in case history. Everyone, managed and jail roles cannot receive grants. Remove automatic role, verification and level reward assignments before delegating a role; delegated roles cannot be awarded or recovered by those features. Only native administrators may assign them using Sonata's role add command. Members who can assign the role directly in Discord can also grant its bot access, so keep the role above untrusted role managers.

Delegatable slash commands have open default visibility so roles without Discord punishment permissions can invoke them; Sonata checks native or delegated authority on every request. Discord's server integration settings can still hide commands or restrict Use Application Commands. See [Discord command permissions](https://docs.discord.com/developers/interactions/application-commands#permissions).

`commandsettings disable ban` disables a whole command; `commandsettings disable settings prefix` disables one subcommand. `enable` restores the matching entry, and `view` lists restrictions. A disabled parent still blocks its subcommands. Prefix aliases and matching dashboard or component actions use the same checks. Help, dashboard, permission grants and command settings cannot be disabled, so managers can recover configuration access.

`commandstats`, `commandstats commands [days]` and `commandstats failures [days]` show command execution results for up to ninety calendar days. Outcomes distinguish success, denied permissions, invalid input, rate limits, busy queues, service errors and cases needing review. Replayed requests do not count twice. Only per-server, per-command daily counters are retained; no message content, command arguments, member IDs or raw errors are stored in analytics. Result tracking begins with this update; earlier aggregate use totals remain available. The server dashboard exposes the same insights, nickname settings, command disabling and administrator-only role grants. The help overview includes a masked Sonata dashboard link.

## Role recovery, exports and music controls

Enable `role recovery on` with Manage Server and Manage Roles. Sonata begins remembering member role IDs from Discord's member snapshot and updates. Use `role restore @member` after a rejoin, within three hours of departure. It grants only basic roles below both moderator and bot, skips managed, deleted, privileged and jail roles, refuses pending or jailed members, and creates a case. Failed or skipped roles keep the original deadline for retries. There are no automatic grants, and earlier departures without a snapshot cannot be recovered. `role recovery off` clears the recovery data. Expired departure snapshots are removed by scheduled maintenance.

`case export USER_ID json`, `csv` or `text` downloads up to one hundred cases, with at most one hundred notes/evidence references per case. A before cursor retrieves earlier cases. It requires Moderate Members and uses only the current server. Evidence files are referenced by link, not copied into the report. CSV exports preserve long IDs and neutralize spreadsheet formulas. Prefix exports are posted in the command channel; slash exports remain private.

`filter bassboost`, `nightcore`, `vaporwave` and `off` switch fixed FFmpeg presets, keeping source position, pause state and volume. A selector also appears on new music cards. Nightcore and vaporwave change speed and pitch; effects last for the current voice session and apply to subsequent queued tracks. Audio processing uses the existing voice host and does not accept arbitrary filter expressions.

`musicsettings djrole @DJ` selects a role; `musicsettings mode dj` restricts playback changes to that role or staff with Manage Server or Move Members. Open mode keeps the original listener controls. Everyone in the channel can queue tracks, browse and use `voteskip`. In DJ mode a non-DJ's ordinary skip becomes a vote. `musicsettings votes 60` sets the required percentage of current human listeners. Listener voice states are checked live, bots and deafened accounts are excluded, and one vote per member counts for the current track. Votes reset for a new track. Voting supports up to fifty connected accounts; staff can skip directly beyond that bound. Only current voice-channel IDs are saved for vote eligibility, not voice audio. DJ and recovery settings are also available in the server dashboard.

## Server dashboard

Use `,dashboard` or [the server dashboard](https://sonata.hurts.workers.dev). Sign in with Discord; Sonata checks current Manage Server permissions separately for every server and action. The existing [Control Room](https://sonata.hurts.workers.dev/admin) has a **Discord bot** tab for its configured owner, showing every bot installation, member snapshots, server details, connection status and activity totals. Owner overview access alone does not grant permission to change another server or browse its cases and tickets.

The Cloudflare services communicate through the BOT_SERVICE binding and a separate BOT_DASHBOARD_SECRET. Use the same random key of at least 32 characters in the ignored bot and service .env files, then run `npm run setup -- --upload-dashboard` here and `node upload-secrets.mjs` in service/cloudflare. Apply the new service migrations before deployment. Discord sign-in keeps the existing identify scope and callback; the bot token never goes into the Control Room, browser or client plugin.

## Hosting

The Worker uses one SQLite-backed Durable Object for the Gateway connection, server settings, cases and scheduled releases. It receives prefix and slash commands through Discord's authenticated Gateway. Leave the application's Interactions Endpoint URL empty; an HTTP interaction endpoint is not required for this design. The existing Control Room OAuth redirect belongs to its separate application and does not change.

The design targets Workers Free. One always-active 128 MiB object uses about 11,060 GB-seconds per day, within the currently documented 13,000 GB-second daily allowance. Requests, SQL operations and storage have separate limits. An outgoing Gateway WebSocket cannot hibernate. This design supports one Gateway connection and must be redesigned for Discord sharding requirements or traffic above the free limits. Free limits stop operations instead of automatically upgrading the plan. See [Durable Objects pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/) and [WebSocket behavior](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).

## First setup

1. Create a separate Discord application named **Sonata Bot**. This workspace uses application `1564909992383877122`.
2. On its Bot page, enable **Server Members Intent** and **Message Content Intent**. Enable **Public Bot** if other server administrators should be able to invite it. Discord requires review for privileged intents as a bot grows.
3. Copy `.env.example` to `.env` only if `.env` does not exist. Fill `DISCORD_APPLICATION_ID`, `DISCORD_BOT_TOKEN`, and a random `BOT_CONTROL_SECRET` of at least 32 characters. The private file in this workspace already contains the application ID and a generated control secret. Keep the token and control secret private.
4. Run `npm install` in this folder, then `npm run setup -- --check`. This checks that the bot token belongs to the expected application.
5. Run `npm run check` and `npm test`. Then run `npm run deploy`. The first deployment stays unconfigured until secrets are saved.
6. Run `npm run setup -- --upload` to send the three private configuration values into this Worker's Cloudflare secret storage. Values use the tool's standard input and are not printed. This requires authorization to your own Cloudflare account using Wrangler.
7. Run `npm run setup -- --register` to register the slash commands. Leave `TEST_GUILD_ID` empty for global commands, or use an already-installed test server for guild-only registration.
8. Open `https://sonata.hurts.workers.dev/invite`, choose your server and approve the required permissions. Approve Administrator for the bot. Move the bot's role above the members it should moderate.
9. Run `npm run setup -- --start`, then `npm run setup -- --status` to check the connection. If Discord reports missing privileged intents, enable them in the portal and run `--start` again.
10. In your server, use `/settings modlog` to select a staff log channel, `/jailsetup` if you want jail, and `/settings dm` if you want punishment DMs. Test with `/ping` and `,ping` before using moderation actions.

For updates, run `npm run check`, `npm test` and `npm run deploy`. Run `--register` when command definitions change. Deployments keep the Durable Object's saved data. Use `--stop` to pause the Gateway until `--start` is called again. The one-minute scheduled trigger reconnects after temporary failures and processes timed releases while running.

If status still reports the previous command count after deployment, temporarily stop the voice companion with `sudo docker compose stop` in its server folder, stop the Gateway, wait forty-five seconds without polling, then start the Gateway and companion again. This releases the previous running instance while preserving the database. Active music playback disconnects during this restart.

## Moderation behavior and stored data

The server's real Discord permissions and role hierarchy are checked for every moderation command. The bot also needs the permissions and hierarchy required to perform it. Staff settings cannot grant permissions that bypass these checks. Server owners cannot be targeted, and a moderator cannot target themselves or Sonata Bot. Prefix and slash commands share validation and cases. Replayed Gateway commands cannot repeat an accepted action.

Cases record the server, target, moderator, reason, duration, status and staff notes. An ambiguous or failed action is marked for review. Case access requires moderation permissions in that server. This bot does not use the Control Room activation registry or collect general chat history. Gateway message content is processed to recognize commands and is not saved as a message archive. Accepted command IDs are retained for seven days to prevent duplicate actions. Cases and server settings remain until the operator removes them.

The bot dashboard additionally stores selected metadata only for servers where the bot is installed, XP totals and cooldowns, public AFK messages, ticket routing details, lockdown permission snapshots, custom aliases and daily command counters. Counters expire after ninety days and contain no arguments or message text. Bot dashboard sign-ins use separate twelve-hour sessions and do not create Sonata activation records.

Configured server tools additionally save protection event counters, current voice channel IDs for voice logging, short-lived form submissions, appeal text and staff decisions, ticket records and giveaway entries/results. Ticket transcript exports intentionally copy the latest ticket messages into a file in the configured Discord transcript channel. General event logs do not archive ordinary message content. See [server tools setup](SERVER_TOOLS.md) for the scope and limits of each optional feature.

`case evidence` accepts image/video attachments up to 8 MiB. The bot copies the actual file into the configured Discord staff log channel and saves that message's link with the case. Keep the Discord log message to retain its file. Case reasons, notes and evidence links are stored in the bot's SQLite data; files remain on Discord. Copying can fail if Discord refuses the attachment or bot upload permissions are missing.

Lock and hide modify the everyone overwrite; explicit role/member allows and administrators can still bypass that overwrite. Unlock/unhide restore only the permission bits Sonata changed, preserving unrelated edits. Jail setup creates a role and private channel, supports up to 100 existing channels, and saves the member's original roles for release. Jail does not grant new roles during restoration; role hierarchy is checked against the saved roles too. Keep the bot's role and permissions in place so scheduled releases can complete.

Punishment DMs are off by default. If enabled, the bot reports DM failures separately from successful moderation actions. A later ban with a different reason is kept when an older temporary ban expires. Actions performed by other bots or manually in Discord do not automatically become Sonata cases.

Enabling ban appeals also enables its pre-ban form notices, even when general punishment DMs are off. Appeal approval records an unban case and staff decision while keeping the original ban case and evidence.
